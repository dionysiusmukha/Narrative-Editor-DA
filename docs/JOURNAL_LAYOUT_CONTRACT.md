# Авторские страницы дневника · контракт 1

Источник истины для игры и следующего экспорта Narrative Editor: этот документ и [JSON Schema](../content/journal/journal_layout.schema.json). Версия `schema_version: 1`. Это расширение существующего Journal, не новый дневник. Принято по запросу владельца 2026-11-06, [ADR-0066](decisions/0066-authored-journal-layout.md).

## Подключение

`DialogueCatalog.load_files(glossary_path, dialogue_paths, variables_path = "res://content/variables/narrative_variables.json", journal_layout_path = "") -> bool` атомарно загружает комплект; `load_journal_layout(path) -> bool` атомарно добавляет композицию к уже загруженному каталогу **до** Journal.configure. Ошибки доступны в `validation_errors`. `get_journal_layout() -> Dictionary` возвращает независимую копию. `Main.journal_layout_path` — необязательное экспортируемое поле. Пустой путь оставляет прежний контент и раскладку без изменений. Никакой неявной подмены каталога или сканирования чужих пакетов нет.

Файл по принятому пути `content/journal/journal_layout.json` сейчас содержит только явно отмеченный TEST «Северный сектор». Его словарь и диалог — `test_north_terms.json` и `test_north_dialogue.json` в той же папке. Не подключать его к старому словарю: отсутствующие ссылки отклоняются. Обычная стартовая сцена сохраняет прежний контент. Готовая демо-сцена: `tests/journal_layout_demo.tscn`.

## Точная структура

Все перечисленные поля сущностей обязательны, если не указано иначе. Неизвестные поля отклоняются; необязательные настройки находятся внутри `style`/условий. ID — `^[a-z][a-z0-9_]*$`, до 80 символов; уникальны во всём layout, включая варианты исправлений. ID ссылок остаются ID существующих реестров, отображаемый текст не используется как ключ.

| Сущность | Поля |
| --- | --- |
| Корень | `schema_version: 1`, `id: string`, `test_content: bool`, `pages: Page[]`, `connections: Connection[]`, `interactions: Interaction[]` |
| Page | `id`, `section: "notes" или "words"`, `title: string` (1–120), `order: integer >= 0`, `elements: Element[]`, `reveal_condition: Condition` |
| Element | `id`, `type`, `reference_id: string`, `position: [x,y]`, `size: [w,h]`, `style: Style`, `reveal_condition: Condition` |
| Connection | `id`, `source_id`, `target_id` (ID элементов одной страницы), `path_points: [x,y][]`, `style: Style`, `activation_condition: Condition` |
| Interaction | `id`, `type: "compare", "connect" или "revise"`, `source_ids: string[]`, `options: Option[]`, `activation_condition: Condition`, `strike_ids: string[]` |
| Option исправления | `id`, `text: string` (1–240) |

Порядок страниц — возрастающий `order`, уникальный внутри раздела. Номер на бумаге — `order + 1`; разделы нумеруются независимо. Пропуски номеров допустимы. «Рецепты» используют существующий `journal_recipes` и прежнюю пагинацию. Указатель тем — обычная авторская страница с элементами `page_link`; никакого отдельного реестра тем нет.

Координаты нормализованы в пределах **рабочей области PaperPages**, а не окна или всей текстуры с пружиной. Начало сверху слева, x вправо, y вниз. `position` — верхний левый угол, `size` — ширина/высота; положительные размеры, вся область в [0,1]. Позиции скрытых записей не пересчитываются. Нижние 0,10 высоты желательно оставлять для временной полоски/возврата; верхние 0,08 — под заголовок. Автор отвечает за взаимное расположение областей; автоматическая упаковка не выполняется.

| Тип элемента | `reference_id` и поведение |
| --- | --- |
| `quote` | ID существующего термина: текст `description`, свидетельство уже получено через обычный `grant_term`, источник хранится в Journal entry. Клик выбирает цитату для сопоставления |
| `term` | ID термина: `title`, ниже — история предполагаемых значений; клик открывает доступное `revise` |
| `group` | ID существующей reasoning_group. На фиксированных местах показываются только известные слова. Порог/варианты/предпосылки читаются из JournalReasoning; клик по готовой группе открывает бумажный список. После выбора готовую группу можно выбрать для `connect` |
| `conclusion` | ID существующего варианта reasoning_group. Текст показывается только после выбора этого варианта. Для альтернатив автор размещает несколько таких элементов в одной области |
| `page_link` | ID страницы layout; строка «см. стр. …»; переход с существующим физическим листанием. Ссылка скрыта, если целевая страница ещё недоступна |

Группа видна после первого известного слова, контур — после `minimum_terms`, варианты — только при выполненных `required_conclusions`. Старый лимит четырёх групп на одном листе снят; общий защитный лимит реестра остаётся 32. Номер `sheet` реестра групп нужен старому контенту; размещение импортированной группы определяется Element, независимо от этого номера.

`Style` — объект с необязательными `font_size` (целое 22–48), `layer` (целое 0–100), `contour` (3–128 нормализованных точек внутри области элемента), `arrow` (bool, для линии, default true), `curve` (bool, default false). Без contour используется детерминированный неровный карандашный контур. `path_points` соединения — 2–128 точек в координатах всей рабочей области, сохраняются в авторском порядке, соединяются с лёгкой штриховой неоднородностью; при `curve: true` кривая проходит через авторские узлы с касательными из соседних узлов (кубическая интерполяция, не автоматическая прокладка); автоматический обход записей не заменяет этот маршрут. Порядок слоёв возрастающий: default 0 у соединений, 10 у элементов; при равенстве — порядок файла.

`Condition` — объект с необязательными массивами `terms`, `conclusions`, `completed`. Все перечисленные ID должны быть известны/выбраны/выполнены; пустой объект означает отсутствие дополнительных требований. Повторы и отсутствующие ID запрещены. `completed` ссылается только на compare/connect; циклические зависимости отклоняются. Условия не выдают знаний и не оценивают истинность. Они дополняют обязательную проверку полученного термина, порога группы и видимости страницы. Скрытые тексты/варианты не рисуются и не получают кликов. Заголовок доступной страницы должен быть безопасным для показа.

`compare` требует две quote, `connect` — две group; порядок выбора концов неважен. В обоих случаях options пуст, действие выполняется один раз после фактического выбора обеих доступных записей. Несценарная пара тихо снимает выбор. `compare` подчёркивает обе цитаты и пишет «Не сходится?»; это не доказательство лжи. `strike_ids` задаёт видимые записи, которые надо визуально зачеркнуть; их семантические выводы не удаляются. `connect` активирует линии с подходящим условием completed. `revise` требует один term и 2–8 вариантов options; повтор текущего значения ничего не меняет, предыдущие выборы сохраняются (до 128 правок на весь дневник). На бумаге остаются два последних значения, старшее зачёркнуто; полный архив не теряется.

Выбор интерпретации группы использует существующий `Journal.choose_conclusion` и существующий option ID, а не дублирующий Interaction типа interpret. Произвольные effects, выдача терминов, установка переменных и команды мира из layout не исполняются. Это сознательная граница версии 1.

## Состояние, сохранения и совместимость

Journal владеет `investigation: JournalInvestigation`; layout — только определения. `export_progress()` добавляет необязательный блок:

```json
{"investigation":{"layout_id":"test_north_layout","completed":["north_discrepancy"],"revisions":[{"interaction_id":"north_meaning","option_id":"meaning_gate"}],"presented":["quote_supply"]}}
```

Здесь `presented` содержит ID уже показанных элементов/линий/пометок или выбранных вариантов исправлений. Таймеры, координаты, весь layout, временная выбранная цитата и стек возврата **не** сохраняются. Основные термины/источники и conclusions остаются в прежних полях. Состояние идёт через существующий checkpoint в `user://` на границе смены, а не в исходники или сцену; закрытие книги не является новым автосохранением. После восстановления уже показанное письмо не повторяется. Одновременные новые записи проявляются параллельно, без длинной очереди; клик/переход заканчивает текущие проявления, reduced/off мгновенные, меню ставит часы на паузу.

Восстановление атомарно: проверяются ID layout, доступность источников/вариантов, зависимости, повторы и формы полей, затем заменяется состояние Journal. Старые checkpoint без investigation принимаются. Старые наборы без layout не получают нового блока. Отпечаток прежнего контента не меняется от координат layout; несовместимые удалённые ID дают отказ с сохранением файла прежним CheckpointStore. При переименовании ID нужна отдельная миграция; импорт не угадывает соответствия. `make_visual_copy()` копирует layout/состояние, а физический target → live передаёт ту же композицию и временную полоску без изменения знания.

Защитные пределы: файл 1 МиБ, 128 страниц, 128 элементов на страницу/512 всего, 512 соединений, 256 взаимодействий, 128 точек маршрута. Это пределы пакета, не ограничение «3–5 групп на листе». JSON Schema проверяет форму; Godot дополнительно проверяет ссылки, типы источников, общую уникальность, границы областей и циклы. Повреждённый пакет отклоняется целиком; прежний каталог остаётся доступен, частичная расстановка или подстановка секретного текста не выполняется.

## Согласование с Narrative Editor

Проверены [типы](https://github.com/dionysiusmukha/Narrative-Editor-DA/blob/main/src/types/narrative.ts), [экспортёр](https://github.com/dionysiusmukha/Narrative-Editor-DA/blob/main/src/utils/godotExporter.ts) и [свидетельства](https://github.com/dionysiusmukha/Narrative-Editor-DA/blob/main/docs/TESTIMONY_SYSTEM.md) 2026-11-06. Текущий экспорт содержит прежние terms/reasoning_groups/options/recipes; их формат и ID здесь сохранены. Layout пока не экспортируется. `testimony_links` остаются редакторскими данными, пакет narrative_events относится к другой интеграции памяти; в текущей игровой ветке нет общего реестра этих свидетельств. Поэтому версия 1 ссылается на уже полученные записи Journal по term ID с существующим источником, а не объявляет незагруженный testimony известным.

Следующий шаг редактора: добавить в NarrativeProject авторский layout по этой схеме, валидировать ссылки в общем проекте и выгружать отдельный `content/journal/journal_layout.json`. Свидетельство, предназначенное для показа игроку в этой версии, экспортируется как запись существующего terms с устойчивым ID и выдаётся штатным grant_term в нужном узле; скрытые NPC memories автоматически не выдаются. Для нативного подключения narrative_events/testimony ID потребуется отдельный адаптер полученных свидетельств и новая согласованная версия контракта, а не копирование скрытой памяти в дневник. Репозиторий редактора этой задачей не изменялся.

## Демонстрация и проверка

Запустить `godot --path . res://tests/journal_layout_demo.tscn`. Указатель ведёт на две страницы заметок; N постепенно выдаёт шесть записей в необычном порядке, без перемещения остальных. Группы открывают гипотезы; после выбора первых двух готовые группы можно соединить. Цитату о поставке на стр. 2 сопоставить с цитатой о грузе на стр. 3. После перехода доступна бумажная полоска сравнения; её клик или Esc отменяет выбор. «↶ назад» возвращает по ссылке с физическим листанием. В словаре кликнуть «Створ» и дважды выбрать разные значения. У зависимой группы нужны выводы north_early и north_delivery. Весь текст демонстрации TEST, не канон.

Автоматический сценарий: `godot --headless --path . res://tests/journal_layout_demo.tscn -- --verify`; GPU — без headless, после `--` добавить `--capture`, для 960×600 также `--small --capture-dir=res://artifacts/journal-layout-small`. godot — Godot 4.7.2 stable. Общий `tools/check.ps1` включает сценарий и отдельные процессы записи/чтения checkpoint. [Фактические результаты и файлы](worklog/2026-11-06-journal-layout.md).
