# Старты диалогов и имена персонажей

В верхней панели графа нажмите «Новый диалог»: выберите персонажа и введите название. ID формируется из типа, авторского имени персонажа и названия. Существующие ID остаются постоянными.

В параметрах диалога откройте «Старты и предусловия». Каждый старт имеет название, начальную реплику, минимальную смену, список произошедших и ещё не произошедших событий. Все условия объединены через И. Приоритет определяется порядком правил, его можно изменить кнопкой «Выше по приоритету». Пустой список стартов сохраняет прежний одиночный start_node. Для первого дня добавьте отдельное правило с запрещёнными событиями концовок; для второго — правила с нужными событиями концовок и сменой 2.

В концовках первого дня используйте эффект NPC «Запомнить событие». После следующей смены в симуляторе сначала выберите старт. «Начать с текущей историей» доступно только при выполненных условиях. «Отдельный тест предусловия» создаёт независимое состояние симулятора с нужными событиями и сменой, очищает термины, выводы и эффекты. В проект эта тестовая история не сохраняется.

В карточке персонажа раздел «Имя, которое знает игрок» задаёт имя до знакомства и упорядоченные варианты имени с такими же условиями. Можно создать глобальное событие знакомства в разговоре другого NPC. Симулятор использует первое подходящее имя для говорящего; авторское имя и ID при этом не меняются.

Сохранение проекта включает starts, unknown_name и name_rules. Экспорт передаёт эти поля в JSON диалогов и персонажей только при наличии настроек. Для выполнения новых правил в самой игре потребитель JSON в Godot должен поддерживать их; изменения этого редактора не обновляют код игры. Старые проекты без этих полей сохраняют прежнее поведение и прежний экспорт.
